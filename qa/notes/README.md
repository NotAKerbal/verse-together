# Notes component QA

Run `npm run qa:notes` and open `http://127.0.0.1:4189/qa/notes/index.html`.

This separate Vite harness renders the actual `JournalWorkspace`, `JournalNoteEditor`, Markdown editor and reading-log dialog with explicitly synthetic fixtures. Its auth, mutation and routing shims never contact Clerk, Convex or a production API. It is outside Next's app routes and is not a product sample mode. Fixture state resets on page reload. The fixtures give October 21 five notes (one published, so read-only; one with a long title, a 220-character excerpt and a long source label; one with an unbroken title and excerpt) and a reading, October 20 an older verse note and October 18 one note. The harness opens on October 21's first note, as if arriving from the reader's sidebar with it active; add `?active=none` to arrive without an active note (a phone then starts on the calendar). Day, open and close state go through the same `journalView.ts` model as the app, with the active note standing in for the provider's. The harness header/navigation is only scaffolding; the real app retains its existing header and bottom-nav components.

Backend ownership, persistence, revision conflicts, legacy retention and idempotency are covered separately by `npm run test:notes` using Convex's in-memory test helper. This harness does not establish authenticated end-to-end backend verification.
